# PRD：邮件告警

通用管理系统脚手架中，为失败的操作日志提供全系统唯一一份邮件通知约定，并留下可追查的告警记录。

领域词汇以 `CONTEXT.md` 为准；投递时序以 ADR-0005 为准；品牌视觉引用 `docs/design/DESIGN.md`，本文件不重写 Token。

## 问题陈述

运维需要在写操作失败时尽快被叫醒，但当前只有操作日志列表，不会主动通知。值班邮箱往往不是系统用户，通道参数（邮件服务器、发件人、收件人）需要在运行时配置，并且要能分清「业务操作失败」和「邮件没发出去」。未配好通道时不应堆积无效留痕；发送失败后要能对着同一条记录补投，而不是另起规则引擎。

## 解决方案

提供全系统唯一一份邮件告警约定：配齐邮件服务器、发件人与至少一个收件人后方可启用。仅在已启用时，对之后新产生的失败操作日志立即发信（一封发给全部收件人），并留下与该操作日志一对一的告警记录（摘要快照 + 发送成功或发送失败 + 发送失败原因）。未启用则不发送、不建记录。支持试发（不建记录）、对发送失败记录重新发送（关掉后仍可）、删除记录（删除后不补建）。配置、列表、重新发送、删除为独立菜单权限。Web 管理端系统管理下单一菜单「邮件告警」，页内「约定 | 告警记录」两个页签。

## 用户故事

US-1：作为有配置权限的运维，我想填写邮件服务器、发件人、收件人并保存草稿，以便分步配齐后再启用。

US-2：作为有配置权限的运维，我想在配齐后启用邮件告警，以便对之后新产生的失败操作日志发出通知。

US-3：作为有配置权限的运维，我不希望已启用时把约定保存成不配齐，以免告警在看起来仍开启时失效。

US-4：作为有配置权限的运维，我想在配齐后试发且不产生告警记录，以便启用前验证通道。

US-5：作为运维，我希望已启用时失败操作日志立即发信，并留下一对一告警记录（含摘要快照），以便对照操作日志追查。

US-6：作为运维，我希望未启用时既不发信也不建告警记录，以免列表被必然失败的投递淹没。

US-7：作为有重新发送权限的值班，我想对发送失败的告警记录重新发送（当前未启用也可以），并且只更新同一条记录。

US-8：作为值班，我不希望对发送成功的告警记录再发，以免同一事件刷屏。

US-9：作为有列表权限的人，我想查看告警记录（含发送失败原因），并且列表不受数据权限裁剪。

US-10：作为有删除权限的人，我想删除告警记录，并接受删除后不可从操作日志补建。

US-11：作为权限被拆开的用户，我只能执行被授予的配置、列表、重新发送、删除或试发，不能越权改约定或清记录。

US-12：作为配置者，我不希望获取约定时带回 SMTP 密码明文；保存时密码留空表示不改。

US-13：作为已登录用户，我想从系统管理侧栏进入「邮件告警」，以便找到约定与告警记录。

## UI 与设计要求

**UI 模式**：`spec-driven`（规范驱动 UI）。**UI 设计描述**为编码的唯一权威来源。不要求、不规划设计稿。品牌视觉引用 `DESIGN.md`（创意北极星「控制台对齐」、§5 通用原语、§6 宜忌），禁止在本 PRD 重写色板 HEX 或字号表。

端 / `platform-id`：仅 **Web 管理端**（`web-admin`）。无小程序 / App。

加载中 / 空 / 错误 / 禁用是同一页的状态变体，不是独立 UI 页。

- **端 / 运行环境**：Web 管理端（`web-admin`）
- **page-id**：`email-alert`
- **页面标题**：邮件告警
- **主任务**：配置邮件告警约定，并查看、重新发送、删除告警记录
- **覆盖的用户故事**：US-1~US-12
- **DESIGN 复用**：§5 按钮（主/次/文字）、输入与表单、卡片容器、列表行、状态徽章、空状态、Loading；表单错误引用 `semantic-error`
- **UI 设计描述**：继承 `web-admin` **app-shell**，侧栏「系统管理」下选中「邮件告警」；本页只描述内容区，不重复顶栏/侧栏规格。内容区使用 `PageContainer`，页标题「邮件告警」。标题下方为 antd `Tabs`，两项：「约定」「告警记录」。无配置菜单权限时不渲染「约定」页签，进入页面默认停在「告警记录」。无列表权限则不能停留在本页（与现有无权限菜单隐藏一致）。

  **告警记录页签**（须列表权限）：`ProTable`，中等密度，行底分割线（亮色细分割 / 夜间幽灵描边）。列顺序：ID、操作日志 ID、用户、模块、动作、路径（过长省略）、发生时间、发送状态、发送失败原因（过长省略）、操作。发送状态用 antd `Tag`：发送成功为成功语气，发送失败为错误语气（文字必须带「发送」前缀，禁止裸写「成功」「失败」）。筛选：发送状态、模块、发生时间范围。行操作：发送失败且具备重新发送权限时显示文字按钮「重新发送」；发送成功行不显示该按钮。具备删除权限时显示「删除」，点击后 Popconfirm 确认，确认后删除该行。重新发送中该行按钮 loading。

  **变体段**：加载——约定区 `Spin`，表格内置 loading，复用 §5 Loading。空状态——表格无数据时居中 §5 空状态，主文案「暂无告警记录」，无强制 CTA。错误——接口失败 `message.error`；表单字段级 `semantic-error`。试发成功 `message.success`「测试邮件已发送」，不跳转页签、不新增表格行。删除确认不作为独立页。

## 实现决策

### 邮件告警领域服务

新建领域服务作为配置保存/启用、失败操作日志触发投递、重新发送、试发、删除的唯一业务入口。操作日志中间件在写失败日志落库并取得 ID 后调用该入口；不在中间件内直连 SMTP。词汇与规则以 `CONTEXT.md` 为准。

### 邮件发送端口

领域服务依赖可替换的发送端口（From、收件人列表、主题、正文）。生产实现走 SMTP；测试使用假实现记录调用与错误。一次投递一封邮件发给全部收件人，一个发送结果。

### 邮件告警约定持久化

约定以数据库中全局唯一一份记录保存（启用状态、邮件服务器主机/端口/加密方式/认证用户名/密码、发件人显示名与地址、收件人列表）。不放环境变量。邮件服务器配齐指：主机、端口、加密方式（含「无」）、认证用户名、密码均非空（更新时密码留空且库中已有密码视为已配齐）。另须发件人地址与至少一个收件人才能启用。未启用允许保存不完整草稿；已启用时保存成不配齐必须拒绝。

### SMTP 密码处理

密码明文入库。读取约定的接口不返回密码明文，只表达已配置或未配置。保存时密码字段缺省或空字符串表示不修改已有密码。

### 操作日志失败后异步投递

遵循 ADR-0005：失败写操作的业务请求不等待 SMTP。先持久化操作日志并取得 ID，再在独立于操作日志 256 工作槽的路径上发信，最后写入告警记录的最终状态（发送成功或发送失败）。无待发送态。重新发送与试发由人工触发，可等待本次 SMTP 结果再返回 HTTP。

### 告警记录持久化

告警记录与失败操作日志一对一；含操作日志 ID、发送时摘要快照（用户、模块、动作、路径、错误信息、发生时间）、发送状态、最近一次发送失败原因。发送成功后清空发送失败原因。列表不套数据权限。删除后不因原操作日志仍在而重建；重新发送对象不存在则失败。

### 菜单权限

系统管理下菜单「邮件告警」，按钮权限拆为四项：配置（查看/保存约定、启用/关闭、试发）、告警记录列表、重新发送、删除。标识建议与现有 `system:*` 风格一致：`system:email-alert:update`、`system:email-alert:list`、`system:email-alert:resend`、`system:email-alert:delete`。无配置权限不展示约定页签。

### GET/PUT 邮件告警约定

`GET /api/v1/system/email-alert` 需配置或列表权限之一即可读（列表权限只读、不返回密码；无配置权限不得写）。`PUT /api/v1/system/email-alert` 需配置权限，body 含启用开关与约定字段；启用为真时服务端校验配齐。密码不出现在 GET 的 data 中，另给 `password_configured` 布尔。

### POST 试发

`POST /api/v1/system/email-alert/test-send` 需配置权限；未配齐返回错误；成功不创建告警记录。

### GET 告警记录分页

`GET /api/v1/system/email-alert/records` 需列表权限；支持发送状态、模块、时间范围筛选；不分数据权限。

### POST 重新发送告警记录

`POST /api/v1/system/email-alert/records/:id/resend` 需重新发送权限；仅发送失败可成功；未启用也可调用。

### DELETE 告警记录

`DELETE /api/v1/system/email-alert/records/:id` 需删除权限。

### 失败操作日志触发

操作日志创建成功且状态为失败、且约定已启用且配齐时，异步走领域服务投递。成功操作日志不触发。同一操作日志已有告警记录则不新建（一对一）。

## 测试决策

好的测试只断言可观察行为（约定是否启用、告警记录列表内容、假发送端口是否被调用及收件人、HTTP 状态与权限拒绝），不断言内部协作对象调用次数，不以直接查库作为唯一断言。主接缝为邮件告警领域服务 + 假发送端口；权限与密码形状走 HTTP API 集成（先例：现有系统 ping/login 风格的 HTTP 测试）。Web UI 测页签、按钮显隐、空态文案与禁用，不测像素。Playwright E2E 不作为本需求门禁。

### 邮件告警领域服务 / 未配齐不能启用

缺主机、或无密码、或无发件人、或收件人为空时启用失败，约定仍为未启用。

### 邮件告警领域服务 / 配齐后可以启用

主机、端口、加密方式、用户名、密码、发件人地址、至少一个收件人均有时可以启用。

### 邮件告警领域服务 / 未启用可存不完整草稿

未启用时保存缺项配置成功，仍为未启用。

### 邮件告警领域服务 / 启用中拒绝保存不配齐

已启用时清空收件人并保存被拒绝，仍为启用，收件人不变。

### 邮件告警领域服务 / 启用后失败操作日志建发送成功记录

已启用且假发送成功时，产生一条失败操作日志后恰好一条告警记录为发送成功；含该操作日志 ID 与摘要快照；假端口一次调用，收件人为配置中的全部地址。

### 邮件告警领域服务 / 未启用不落记录

未启用时产生失败操作日志，不出现告警记录，假发送端口未被调用。

### 邮件告警领域服务 / 成功操作日志不告警

已启用时产生成功操作日志，不出现告警记录。

### 邮件告警领域服务 / 一对一不重复建记录

该失败操作日志已有告警记录时再次触发，记录数仍为 1。

### 邮件告警领域服务 / 发送失败原因与操作错误分离

假发送失败时告警记录为发送失败；发送失败原因非空，且不等于快照中的操作错误信息。

### 邮件告警领域服务 / 多收件人一封一个结果

三个收件人且整次发送失败时，仍只有一条告警记录。

### 邮件告警领域服务 / 仅发送失败可重新发送

对发送成功的告警记录重新发送被拒绝，不新增记录。

### 邮件告警领域服务 / 重新发送更新同一条

发送失败记录在假发送改为成功后重新发送，仍为同一条，状态为发送成功，发送失败原因已清空。

### 邮件告警领域服务 / 关掉后仍可重新发送

告警记录为发送失败、当前未启用、约定仍配齐时，重新发送成功并更新该记录。

### 邮件告警领域服务 / 试发不建告警记录

已配齐（不必启用）时试发成功，假端口被调用，告警记录数为 0。

### 邮件告警领域服务 / 未配齐不可试发

收件人为空时试发失败，假端口未被调用。

### 邮件告警领域服务 / 删除后不补建

删除告警记录后，对原失败操作日志再次触发或重新发送，不重建记录；重新发送因对象不存在而失败。

### HTTP API 集成 / 告警记录不套数据权限

调用方仅有列表权限且数据权限为「仅本人」时，仍能列出由他人失败操作触发的告警记录。

### HTTP API 集成 / 菜单权限拆分

无配置权限时保存、启用、试发被拒绝；无重新发送权限时重新发送被拒绝；无删除权限时删除被拒绝；无列表权限时分页列表被拒绝。

### HTTP API 集成 / 密码不回传且留空不改

GET 约定不含密码明文，并能表示已配置；随后 PUT 只改收件人且密码留空，之后假发送仍使用原密码。

### HTTP API 集成 / 异步不挡写操作请求

已启用时，一次会失败的写操作业务响应在 SMTP 完成前返回；告警记录在假发送结束后可查到最终状态，且不出现待发送。

### Web UI / 约定与告警记录页签

同时有配置与列表权限时可见两个页签；仅列表权限只见告警记录页签；未配齐时启用开关与试发禁用；发送成功行不显示「重新发送」。
