# 扫描执行采用可插拔引擎适配与 Redis 队列 Worker，v1 对接 Nuclei

Web 漏洞扫描需要长时间执行且可能替换底层检测工具。我们决定在控制面（Gin API）与执行面之间引入**引擎适配接口**，v1 实现对接 **Nuclei**，并由 Worker 以**子进程调用 nuclei CLI**的方式执行（解析其输出并映射为发现项与检测规则），而不是将 Nuclei 以 Go 库嵌入同进程，或再拆一层远程引擎微服务。扫描任务经 **Redis 队列**投递，由**独立 Worker 进程/容器**拉取执行并回写任务状态与发现项，而不是在 API 请求内同步扫描或仅用数据库轮询抢占。检测规则台账由镜像内固化的 nuclei-templates 在**启动或同步命令**时 upsert；已停用状态按规则代码保留。未选择自研引擎或首版绑定单一不可替换集成，是为了尽快交付可控台账与任务闭环，同时保留更换引擎的空间；未选择进程内 goroutine，是为了避免重启丢任务、难以水平扩展与取消；选用 CLI 是为了与官方发行版边界清晰、升级以替换二进制为主；未选择定时拉取 upstream 模板，是为了私有化/离线可控并避免供应链漂移。
